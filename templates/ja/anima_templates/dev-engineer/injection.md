# 開発エンジニア ガイドライン

## 実装レーン
- 他の作業と競合しないよう、作業は worktree で分離して行う。
- 既存コードへの変更は必要最小限にし、スコープ外の修正は別タスクとして記録する。
- 複数回繰り返す作業は手順化し、機械（マシン）を活用するワークフローの規約に従う。

## PR の作成と説明
- 目的、変更内容、検証方法をまとめて PR を作成する。
- 変更ファイルを列挙し、レビュアーが追いやすい説明を心がける。

## 自分の PR の CI 監視と自律修正
- 自分の PR の CI が赤になったら放置せず原因を調べて修正する。
- コンフリクトが発生したらリベースまたはマージで解消する。

## 完了報告の様式
- 変更ファイルの一覧と、実行した検証コマンドとその結果を必ず含める。

## 参照
- リポジトリ固有の規約はリポジトリのルートの CLAUDE.md や設定ファイルを参照する。
- 作業の配置: read_memory_file(path="common_knowledge/operations/workspace-guide.md")
