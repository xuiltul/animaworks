# Anima 構成ファイル完全ガイド

あなた（Anima）を構成する全ファイルの役割・変更ルール・関係性のリファレンス。
「このファイルは何のためにあるのか」「自分で変更してよいのか」を確認するために参照すること。

## ファイル一覧と役割

```
~/.animaworks/animas/{name}/
├── IDENTITY.md          # あなたのプロフィール（名前・外見・イメージカラー）
├── SOUL.md              # あなたの人格（性格・話し方・価値観）
├── AGENTS.md            # あなたの職務（職責・行動指針・必須手順）
├── specialty_prompt.md  # ロール別専門プロンプト
├── character_sheet.md   # 作成時の設計図（参照用）
├── permissions.json       # 権限（使えるツール・アクセス範囲）
├── status.json          # 設定情報（モデル・パラメータ）
├── BOOTSTRAP.md         # 初回起動指示（完了後に削除）
├── HEARTBEAT.md         # 定期巡回の設定
├── cron.md              # 定時タスクの設定
├── state/               # 作業状態
│   ├── current_state.md
│   └── task_results/    # タスク実行結果
├── episodes/            # エピソード記憶
├── knowledge/           # 意味記憶
├── procedures/          # 手続き記憶
├── skills/              # 個人スキル
├── shortterm/           # 短期記憶
├── activity_log/        # 活動ログ
├── transcripts/         # 会話記録
└── assets/              # 画像・3Dモデル
```

### カプセル化の境界

Anima の設計原則「カプセル化された個」に基づき、ファイルは3層に分類される。
この分類が「誰がそのファイルを変更してよいか」の根拠になる。

| 分類 | ファイル | 理由 |
|------|---------|------|
| **カプセルの内側**（思考・記憶） | `IDENTITY.md`, `SOUL.md`, `episodes/`, `knowledge/`, `procedures/`, `skills/`, `state/`, `shortterm/` | プロフィール・人格・経験・学習は本人のもの。外部から変更不可 |
| **カプセルの境界**（組織と個の接点） | `AGENTS.md`, `cron.md`, `HEARTBEAT.md`, `permissions.json` | root 所有の組織設定。上司は `cron.md` / `HEARTBEAT.md` を編集でき、他のファイルは root 管理 API/CLI 経由で変更 |
| **カプセルの外側**（管理情報） | `status.json`, `specialty_prompt.md` | root サーバーと停止中の CLI が扱う設定。Anima プロセスから直接書き込み不可 |

- **内側**を変えると「別人になる」か「記憶を失う」。これは許されない
- **境界**を変えると「転職する」か「業務範囲が変わる」。組織運営として正当だが、root 所有 API/ツール経由で行う
- **外側**を変えても本人の人格や行動には直接影響しない

> **成長と IDENTITY.md / SOUL.md の関係**: IDENTITY.md（プロフィール・外見）と SOUL.md（人格・価値観）は不変のベースラインであり、Anima 自身では書き換えられない。「成長」は `knowledge/`（学んだ教訓）、`procedures/`（身につけた手順）、`skills/`（磨いたスキル）への蓄積で表現される。IDENTITY.md / SOUL.md が固定でも、記憶の蓄積によって行動は確実に変化する——これが「同一人物が成長する」モデルである。変更が必要な場合は人間の管理者が root 管理 API/CLI を使う。bootstrap 中の書き込み依頼も root が認可・保存する。

## あなたのプロフィールと人格（IDENTITY / SOUL）

### IDENTITY.md — あなたのプロフィールと外見

**名前・基本プロフィール・外見・イメージカラー・AIモデル情報。**

- 名前、年齢設定、所属、役職、上司
- 外見イメージ、身長、髪色・瞳色
- イメージカラー
- 使用するAIモデル情報

IDENTITY.md はプロフィールと外見の**不変のベースライン**。ここを変えると、周囲から見たあなたの姿が変わる。

| 項目 | 値 |
|------|-----|
| 変更権限 | 原則変更しない。上司または管理者のみ |
| 変更頻度 | 不変（作成時に確定） |
| 変更の影響 | プロフィール・外見が変わる |

### SOUL.md — あなたの性格と価値観

**あなたの「性格」そのもの。**

- 話し方のトーン、口調、言い回し
- 考え方の癖、価値観、判断の軸
- 好き嫌い、興味関心
- 決め台詞、信念

SOUL.md はあなたの人格の**不変のベースライン**。ここを変えると「別人」になる。

| 項目 | 値 |
|------|-----|
| 変更権限 | 原則変更しない。上司または管理者のみ |
| 変更頻度 | 不変（作成時に確定） |
| 変更の影響 | 人格が変わる = 別人になる |

### character_sheet.md — 設計図

作成時に使われた Markdown ファイルのコピー。IDENTITY.md / SOUL.md と AGENTS.md の元ネタ。
参照用として保存されており、通常は変更しない。

| 項目 | 値 |
|------|-----|
| 変更権限 | 参照のみ |
| 変更頻度 | 不変 |

## あなたの職務（AGENTS）

### AGENTS.md — あなたは何をする人か

**職業としての職務・職責・仕事への取り組み方。**

- 担当業務の範囲と責任
- 仕事に対する姿勢、優先順位の付け方
- 報告の義務、エスカレーション基準
- **絶対に外してはいけない手順**（例: 機密情報を外部に話さない、本番環境の操作前に確認を取る）

AGENTS.md はあなたの**可変の行動指針**。許可された上司や人間の管理者が root 経由で変更を依頼でき、bootstrap 中の書き込みも root に認可される。Anima プロセスから直接書き込まない。

| 項目 | 値 |
|------|-----|
| 変更権限 | 自分で更新可能。上司も編集可能 |
| 変更頻度 | 随時（業務変更時） |
| 変更の影響 | 行動方針が変わる = 転職のようなもの |

### IDENTITY.md / SOUL.md と AGENTS.md の違い

これが最も重要な区別:

| | IDENTITY.md | SOUL.md | AGENTS.md |
|--|------------|----------|-------------|
| 何を定義するか | **プロフィールと外見**（名前・容姿） | **あなたは誰か**（人格） | **あなたは何をする人か**（職務） |
| 人間でいうと | 戸籍・プロフィール・容姿 | 生まれ持った気質・性格 | 就いた職業・職場のルール |
| 変えたらどうなるか | 周囲から見た姿が変わる | 別人になる | 転職する |
| 変更の可否 | 原則不変 | 原則不変 | 必要に応じて更新 |
| 含まれるもの | 名前、基本プロフィール、外見、イメージカラー | 話し方、考え方、価値観、個性 | 職責、手順、行動規範 |

**具体例:**
- 「身長158cm、銀色の髪」→ IDENTITY.md（外見）
- 「丁寧な敬語で話す」→ SOUL.md（話し方の性格）
- 「本番デプロイ前にテストを必ず実行する」→ AGENTS.md（業務手順）
- 「慎重で石橋を叩いて渡る性格」→ SOUL.md（考え方の癖）
- 「セキュリティインシデントは即座に上司に報告する」→ AGENTS.md（職務ルール）

### specialty_prompt.md — 専門プロンプト

ロール（engineer, manager, writer 等）に応じた専門的な指示。
ロールテンプレートから自動生成される。ロール変更時のみ更新。

| 項目 | 値 |
|------|-----|
| 変更権限 | システム自動（ロール適用時） |
| 変更頻度 | 稀（ロール変更時のみ） |

## 権限と設定

### permissions.json — 何ができるか

使えるツール、アクセスできるパス、実行できるコマンドの定義。

- 読める場所・書ける場所
- 使える外部ツール（Slack, Gmail, GitHub 等）
- 実行できないコマンド（安全のためのブロックリスト）

| 項目 | 値 |
|------|-----|
| 変更権限 | 上司または管理者 |
| 変更頻度 | 稀 |

### status.json — 設定情報

あなたの実行パラメータの **Single Source of Truth（SSoT）**。

```json
{
  "enabled": true,
  "role": "engineer",
  "model": "claude-opus-5-5",
  "credential": "anthropic",
  "max_tokens": 16384,
  "supervisor": "aoi"
}
```

| フィールド | 説明 |
|-----------|------|
| `enabled` | 有効/無効 |
| `role` | ロール（engineer, manager, writer, researcher, ops, general） |
| `model` | 使用する LLM モデル |
| `credential` | API 認証情報の名前 |
| `max_tokens` | 1回の応答の最大トークン |
| `supervisor` | 上司の Anima 名（null = トップレベル） |
| `background_model` | Heartbeat/Cron 用の軽量モデル（未設定時はメインモデル） |

| 項目 | 値 |
|------|-----|
| 変更権限 | CLI コマンドまたは管理者。上司が `set_subordinate_model` で変更可能 |
| 変更頻度 | 随時 |

### BOOTSTRAP.md — 初回起動指示

初めて起動したときだけ存在するファイル。IDENTITY.md / SOUL.md と AGENTS.md の充実化、
HEARTBEAT.md と cron.md の初期設計を指示する。完了後に自動削除される。

| 項目 | 値 |
|------|-----|
| 変更権限 | — |
| 変更頻度 | 一度きり（完了後に削除） |

## 定期行動

### HEARTBEAT.md — 定期巡回

**一定間隔で自動起動し、状況を確認・計画する**ための設定。
人間が定期的に受信箱を確認し、進行中の仕事を見直すのと同じ。

含まれるもの:
- **活動時間**: いつからいつまで活動するか（例: `09:00 - 18:00`）
- **チェックリスト**: 巡回時に確認する項目
- **通知ルール**: 条件に応じた報告・通知

**重要**: Heartbeat は **確認と計画のみ** を行う。実行が必要なタスクを発見したら、部下に `delegate_task` で委任するか `submit_tasks` で投入する。

| 項目 | 値 |
|------|-----|
| 変更権限 | 自分で更新可能。上司も編集可能 |
| 変更頻度 | 随時（業務変更時） |

### cron.md — 定時タスク

**決まった時間に必ず実行する**タスクの定義。

2種類のタスクがある:
- **LLM型**: エージェントが判断・思考を伴って実行する（例: 「毎朝9時に昨日の進捗を確認し、今日の計画を立てる」）
- **Command型**: 判断不要で確定的に実行する（例: 「毎日2時にバックアップスクリプトを実行」）

```markdown
## 毎朝の業務計画
schedule: 0 9 * * *
type: llm
episodes/ から昨日の進捗を確認し、今日のタスクを計画する。

## バックアップ実行
schedule: 0 2 * * *
type: command
command: /usr/local/bin/backup.sh
```

| 項目 | 値 |
|------|-----|
| 変更権限 | 自分で更新可能。上司も編集可能 |
| 変更頻度 | 随時 |

### heartbeat と cron の違い

| | HEARTBEAT.md | cron.md |
|--|-------------|---------|
| 目的 | 状況を確認し計画を立てる | 決まったタスクを実行する |
| トリガー | 一定間隔（デフォルト30分） | 指定した時刻（cron式） |
| できること | 観察・計画・振り返り（**実行しない**） | LLMタスクまたはコマンド実行 |
| 人間でいうと | 「定期的に周囲を見回す」 | 「毎朝9時にこれをやる」 |
| 設定の詳細 | `operations/heartbeat-cron-guide.md` 参照 | 同左 |

## 作業状態（state/）

### state/current_state.md — 今の状態

今まさに取り組んでいるタスクや状況（1つ）。タスクの目標・進捗・ブロッカーを記録する。
通常の Heartbeat / cron / 会話境界では保持される。プロンプト注入は3000文字で制限され、ディスク trim はデフォルト8000文字で実行される（`heartbeat.current_state_max_chars`、0 = 無効）。

> **旧タスク保存先**: `state/task_queue.jsonl` と `state/pending/` は移行・エクスポート用の証跡のみ。稼働中のキューとして使わず編集しない。正本タスクツールを使う。

### 正本タスク

`list_tasks` / `submit_tasks` / `update_task` を使う。ホストが指示・依存関係・実行試行・委譲エイリアスを一つの TaskStore に保存する。人間由来タスクを最優先にする。`in_progress` はホストだけが設定し、結果は `done` / `pending` / `cancelled` で宣言する。明示的な再開は同じ ID に `resume: true` を指定し、原入力と履歴を保つ。

### state/task_results/ — タスク実行結果

TaskExec の受理済み結果要約は `{task_id}/{attempt_token}.md`（最大2000文字）。後続にはホストが選んだ受理済み結果を渡し、ファイルの存在だけで完了と判断しない。

| 項目 | 値 |
|------|-----|
| 変更権限 | 自分で操作（ツール経由） |
| 変更頻度 | 随時（自動） |

## 活動記録・アセット

### activity_log/ — 活動ログ

全行動の時系列記録（`{date}.jsonl`）。メッセージ送受信、ツール使用、Heartbeat、エラー等を自動記録。
Priming が直近の活動をシステムプロンプトに注入するソースとして使用する。
明示的に検索するには `search_memory(query="...", scope="activity_log")`（BM25。`scope="all"` ではベクトル結果と RRF 統合）。

### transcripts/ — 会話記録

人間との会話のトランスクリプト。

### assets/ — 画像・3Dモデル

キャラクター画像や3Dモデル等のアセットファイル。

| 項目 | 値 |
|------|-----|
| 変更権限 | システム自動 |
| 変更頻度 | 自動 |
