# Anima 구성 파일 완전 가이드

당신(Anima)을 구성하는 모든 파일의 역할·변경 규칙·관계성에 대한 참조.
「이 파일은 무엇을 위해 있는가」「스스로 변경해도 되는가」를 확인하기 위해 참조할 것.

## 파일 목록과 역할

```
~/.animaworks/animas/{name}/
├── IDENTITY.md          # 당신의 프로필 (이름·외모·이미지 컬러)
├── SOUL.md              # 당신의 인격 (성격·말투·가치관)
├── AGENTS.md            # 당신의 직무 (직책·행동 지침·필수 절차)
├── specialty_prompt.md  # ロール別専門プロンプト
├── character_sheet.md   # 作成時の設計図（参照用）
├── permissions.json       # 権限（使えるツール・アクセス範囲）
├── status.json          # 設定情報（モデル・パラメータ）
├── BOOTSTRAP.md         # 初回起動指示（完了後に削除）
├── HEARTBEAT.md         # 定期巡回の設定
├── cron.md              # 定時タスクの設定
├── state/               # 作業状態
│   ├── current_state.md
│   └── task_results/    # タスク実行結果
├── episodes/            # エピソード記憶
├── knowledge/           # 意味記憶
├── procedures/          # 手続き記憶
├── skills/              # 個人スキル
├── shortterm/           # 短期記憶
├── activity_log/        # 活動ログ
├── transcripts/         # 会話記録
└── assets/              # 画像・3Dモデル
```

### 캡슐화의 경계

Anima의 설계 원칙 '캡슐화된 개체'에 따라 파일은 3개 층으로 분류된다.
이 분류가 '누가 그 파일을 변경해도 되는가'의 근거가 된다.

| 분류 | 파일 | 이유 |
|------|---------|------|
| **캡슐의 내부** (사고·기억) | `IDENTITY.md`, `SOUL.md`, `episodes/`, `knowledge/`, `procedures/`, `skills/`, `state/`, `shortterm/` | 프로필·인격·경험·학습은 본인의 것. 외부에서 변경 불가 |
| **캡슐의 경계** (조직과 개체의 접점) | `AGENTS.md`, `cron.md`, `HEARTBEAT.md`, `permissions.json` | root 소유의 조직 설정. 상급자는 `cron.md` / `HEARTBEAT.md`를 편집할 수 있고, 다른 파일은 root 관리 API/CLI 경유로 변경 |
| **캡슐의 외부** (관리 정보) | `status.json`, `specialty_prompt.md` | root 서버와 종료 중인 CLI가 다루는 설정. Anima 프로세스에서 직접 쓰기 불가 |

- **내부**를 바꾸면 '다른 사람이 된다'거나 '기억을 잃는다'. 이것은 허용되지 않는다
- **경계**를 바꾸면 '이직한다'거나 '업무 범위가 바뀐다'. 조직 운영으로서 정당하지만, root 소유 API/도구 경유로 수행한다
- **외부**를 바꿔도 본인의 인격이나 행동에는 직접 영향을 주지 않는다

> **성장과 IDENTITY.md / SOUL.md의 관계**: IDENTITY.md(프로필·외모)와 SOUL.md(인격·가치관)는 불변 베이스라인이며, Anima 자신은 재작성할 수 없다. '성장'은 `knowledge/`(배운 교훈), `procedures/`(익힌 절차), `skills/`(연마한 스킬)에의 축적으로 표현된다. IDENTITY.md / SOUL.md가 고정되어도, 기억의 축적으로 행동은 확실히 변화한다——이것이 '동일 인물이 성장한다'는 모델이다. 변경이 필요한 경우 인간 관리자가 root 관리 API/CLI를 사용한다. bootstrap 중의 쓰기 요청도 root가 인가·저장한다.

## 당신의 프로필과 인격 (IDENTITY / SOUL)

### IDENTITY.md — 당신의 프로필과 외모

**이름·기본 프로필·외모·이미지 컬러·AI 모델 정보.**

- 이름, 나이 설정, 소속, 직책, 상급자
- 외모 이미지, 키, 머리색·눈색
- 이미지 컬러
- 사용하는 AI 모델 정보

IDENTITY.md은 프로필과 외모의 **불변의 베이스라인**. 여기를 바꾸면 주변에서 보는 당신의 모습이 바뀐다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 원칙적으로 변경하지 않음. 상급자 또는 관리자만 |
| 변경 빈도 | 불변(작성 시 확정) |
| 변경의 영향 | 프로필·외모가 바뀜 |

### SOUL.md — 당신의 성격과 가치관

**당신의「성격」그 자체.**

- 말투의 톤, 어조, 표현 방식
- 생각하는 버릇, 가치관, 판단의 축
- 좋고 싫음, 관심사
- 결정적 대사, 신념

SOUL.md은 당신의 인격의 **불변의 베이스라인**. 여기를 바꾸면「다른 사람」이 된다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 원칙적으로 변경하지 않음. 상급자 또는 관리자만 |
| 변경 빈도 | 불변(작성 시 확정) |
| 변경의 영향 | 인격이 바뀜 = 다른 사람이 됨 |

### character_sheet.md — 설계도

작성 시 사용된 Markdown 파일의 복사본. IDENTITY.md / SOUL.md와 AGENTS.md의 원본.
참조용으로 저장되어 있으며, 보통 변경하지 않는다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 참조만 |
| 변경 빈도 | 불변 |

## 당신의 직무(AGENTS)

### AGENTS.md — 당신은 어떤 일을 하는 사람인가

**직업으로서의 직무·직책·일에 대한 태도.**

- 담당 업무의 범위와 책임
- 일에 대한 자세, 우선순위 부여 방식
- 보고 의무, 에스컬레이션 기준
- **절대 놓쳐서는 안 되는 절차** (예: 기밀 정보를 외부에 말하지 않는다, 본배포 환경 조작 전에 확인을 받는다)

AGENTS.md은 당신의 **가변 행동 지침**. 허가된 상급자나 인간 관리자가 root 경유로 변경을 요청할 수 있고, bootstrap 중의 쓰기도 root에게 인가된다. Anima 프로세스에서 직접 쓰지 않는다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 스스로 업데이트 가능. 상급자도 편집 가능 |
| 변경 빈도 | 수시 (업무 변경 시) |
| 변경의 영향 | 행동 방침이 바뀐다 = 이직과 같은 것 |

### IDENTITY.md / SOUL.md와 AGENTS.md의 차이

이것이 가장 중요한 구별:

| | IDENTITY.md | SOUL.md | AGENTS.md |
|--|------------|----------|-------------|
| 무엇을 정의하는가 | **프로필과 외모** (이름·모습) | **당신은 누구인가** (인격) | **당신은 무엇을 하는 사람인가** (직무) |
| 인간으로 치면 | 호적·프로필·모습 | 타고난 기질·성격 | 맡은 직업·직장의 규칙 |
| 바꾸면 어떻게 되는가 | 주변에서 보는 모습이 바뀜 | 다른 사람이 됨 | 전직함 |
| 변경 가능 여부 | 원칙적으로 불변 | 원칙적으로 불변 | 필요에 따라 업데이트 |
| 포함되는 것 | 이름, 기본 프로필, 외모, 이미지 컬러 | 말투, 생각 방식, 가치관, 개성 | 직책, 절차, 행동 규범 |

**구체적 예:**
- 「키 158cm, 은색 머리」→ IDENTITY.md(외모)
- 「정중한 존댓말로 말한다」→ SOUL.md(말투의 성격)
- 「본배포 배포 전에 테스트를 반드시 실행한다」→ AGENTS.md(업무 절차)
- 「신중해서 다리를 두드려 보고 건너는 성격」→ SOUL.md(생각의 버릇)
- 「보안 사고는 즉시 상급자에게 보고한다」→ AGENTS.md(직무 규칙)

### specialty_prompt.md — 전문 프롬프트

역할(engineer, manager, writer 등)에 따른 전문적인 지침.
역할 템플릿에서 자동 생성된다. 역할 변경 시에만 업데이트.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 시스템 자동(역할 적용 시) |
| 변경 빈도 | 드묾(역할 변경 시에만) |

## 권한과 설정

### permissions.json — 무엇을 할 수 있는가

사용할 수 있는 도구, 접근할 수 있는 경로, 실행할 수 있는 명령의 정의.

- 읽을 수 있는 곳·쓸 수 있는 곳
- 사용할 수 있는 외부 도구(Slack, Gmail, GitHub 등)
- 실행할 수 없는 명령(안전을 위한 블록리스트)

| 항목 | 값 |
|------|-----|
| 변경 권한 | 상급자 또는 관리자 |
| 변경 빈도 | 드묾 |

### status.json — 설정 정보

실행 파라미터의 **Single Source of Truth（SSoT）**.

```json
{
  "enabled": true,
  "role": "engineer",
  "model": "claude-opus-5-5",
  "credential": "anthropic",
  "max_tokens": 16384,
  "supervisor": "aoi"
}
```

| 필드 | 설명 |
|-----------|------|
| `enabled` | 활성/비활성 |
| `role` | 역할（engineer, manager, writer, researcher, ops, general） |
| `model` | 사용할 LLM 모델 |
| `credential` | API 인증 정보의 이름 |
| `max_tokens` | 1회 응답의 최대 토큰 |
| `supervisor` | 상급자의 Anima 이름（null = 최상위） |
| `background_model` | Heartbeat/Cron 용 경량 모델（미설정 시 메인 모델） |

| 항목 | 값 |
|------|-----|
| 변경 권한 | CLI 명령 또는 관리자. 상급자가 `set_subordinate_model` 에서 변경 가능 |
| 변경 빈도 | 수시 |

### BOOTSTRAP.md — 최초 시작 지침

처음 시작했을 때만 존재하는 파일. IDENTITY.md / SOUL.md와 AGENTS.md의 충실화,
HEARTBEAT.md와 cron.md의 초기 설계를 지시한다. 완료 후 자동 삭제된다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | — |
| 변경 빈도 | 한 번만(완료 후 삭제) |

## 정기 행동

### HEARTBEAT.md — 정기 순회

**일정 간격으로 자동 시작하여 상황을 확인·계획**하기 위한 설정.
인간이 정기적으로 수신함을 확인하고, 진행 중인 일을 다시 검토하는 것과 같다.

포함되는 것:
- **활동 시간**: 언제부터 언제까지 활동할지 (예: `09:00 - 18:00`)
- **체크리스트**: 순회 시 확인할 항목
- **알림 규칙**: 조건에 따른 보고·알림

**중요**: Heartbeat는 **확인과 계획만** 수행한다. 실행이 필요한 작업을 발견하면, 부하에게 `delegate_task`로 위임하거나 `submit_tasks`로 투입한다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 스스로 업데이트 가능. 상급자도 편집 가능 |
| 변경 빈도 | 수시(업무 변경 시) |

### cron.md — 정시 작업

**정해진 시간에 반드시 실행**하는 작업의 정의.

2종류의 작업이 있다:
- **LLM형**: 에이전트가 판단·사고를 수반하여 실행 (예: 「매일 아침 9시에 어제의 진행 상황을 확인하고, 오늘의 계획을 세운다」)
- **Command형**: 판단 불필요로 확정적으로 실행 (예: 「매일 2시에 백업 스크립트를 실행」)

```markdown
## 毎朝の業務計画
schedule: 0 9 * * *
type: llm
episodes/ から昨日の進捗を確認し、今日のタスクを計画する。

## バックアップ実行
schedule: 0 2 * * *
type: command
command: /usr/local/bin/backup.sh
```

| 항목 | 값 |
|------|-----|
| 변경 권한 | 스스로 업데이트 가능. 상급자도 편집 가능 |
| 변경 빈도 | 수시 |

### heartbeat와 cron의 차이

| | HEARTBEAT.md | cron.md |
|--|-------------|---------|
| 목적 | 상황을 확인하고 계획을 세움 | 정해진 작업을 실행 |
| 트리거 | 일정 간격(기본 30분) | 지정한 시각(cron식) |
| 할 수 있는 것 | 관찰·계획·돌아보기(**실행하지 않음**) | LLM 작업 또는 명령 실행 |
| 인간으로 치면 | 「정기적으로 주위를 둘러본다」 | 「매일 아침 9시에 이것을 한다」 |
| 설정의 상세 | `operations/heartbeat-cron-guide.md` 참조 | 동일 |

## 작업 상태(state/）

### state/current_state.md — 현재 상태

지금 바로 진행 중인 작업이나 상황(1개). 작업의 목표·진행 상황·블로커를 기록한다.
보통의 Heartbeat / cron / 대화 경계에서는 유지된다. 프롬프트 주입은 3000자로 제한되고, 디스크 trim은 기본 8000자로 실행된다(`heartbeat.current_state_max_chars`, 0 = 무효).

> **이전 작업 저장 위치**: `state/task_queue.jsonl`과 `state/pending/`는 이행·내보내기용 증적만. 가동 중인 큐로 사용하지 말고 편집하지 않는다. 정본 작업 도구를 사용한다.

### 정본 작업

`list_tasks` / `submit_tasks` / `update_task`를 사용한다. 호스트가 지시·의존 관계·실행 시도·위임 에일리어스를 하나의 TaskStore에 저장한다. 인간 유래 작업을 최우선으로 한다. `in_progress`은 호스트만이 설정하고, 결과는 `done` / `pending` / `cancelled`으로 선언한다. 명시적 재개는 같은 ID에 `resume: true`을 지정하고, 원입력과 이력을 유지한다.

### state/task_results/ — 작업 실행 결과

TaskExec의 수락된 결과 요약은 `{task_id}/{attempt_token}.md`(최대 2000자). 후속에는 호스트가 선택한 수락된 결과를 전달하고, 파일의 존재만으로 완료로 판단하지 않는다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 스스로 조작(도구 경유) |
| 변경 빈도 | 수시(자동) |

## 기억

기억 시스템의 상세는 `anatomy/memory-system.md`을 참조.

| 디렉터리 | 종류 | 내용 |
|------------|------|------|
| `episodes/` | 에피소드 기억 | 언제 무엇을 했는지의 일일 로그 |

| `shortterm/` | 단기 기억 | 세션 간의 맥락 유지용 |

## 활동 기록·에셋

### activity_log/ — 활동 로그

모든 행동의 시계열 기록(`{date}.jsonl`). 메시지 송수신, 도구 사용, Heartbeat, 오류 등을 자동 기록.
Priming이 최근 활동을 시스템 프롬프트에 주입하는 소스로 사용.
명시적으로 검색하려면 `search_memory(query="...", scope="activity_log")`(BM25. `scope="all"`에서는 벡터 결과와 RRF 통합).

### transcripts/ — 대화 기록

인간과의 대화 트랜스크립트.

### assets/ — 이미지·3D 모델

캐릭터 이미지나 3D 모델 등의 에셋 파일.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 시스템 자동 |
