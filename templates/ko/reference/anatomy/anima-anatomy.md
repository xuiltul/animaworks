# Anima 구성 파일 완전 가이드

당신(Anima)을 구성하는 모든 파일의 역할, 변경 규칙, 관계에 대한 참조.
“이 파일은 무엇을 위한 것인가”, “직접 변경해도 되는가”를 확인할 때 참조하세요.

## 파일 목록과 역할

```
~/.animaworks/animas/{name}/
├── IDENTITY.md          # あなたのプロフィール（名前・外見・イメージカラー）
├── SOUL.md              # あなたの人格（性格・話し方・価値観）
├── AGENTS.md            # あなたの職務（職責・行動指針・必須手順）
├── specialty_prompt.md  # ロール別専門プロンプト
├── character_sheet.md   # 作成時の設計図（参照用）
├── permissions.json       # 権限（使えるツール・アクセス範囲）
├── status.json          # 設定情報（モデル・パラメータ）
├── BOOTSTRAP.md         # 初回起動指示（完了後に削除）
├── HEARTBEAT.md         # 定期巡回の設定
├── cron.md              # 定時タスクの設定
├── state/               # 作業状態
│   ├── current_state.md
│   └── task_results/    # タスク実行結果
├── episodes/            # エピソード記憶
├── knowledge/           # 意味記憶
├── procedures/          # 手続き記憶
├── skills/              # 個人スキル
├── shortterm/           # 短期記憶
├── activity_log/        # 活動ログ
├── transcripts/         # 会話記録
└── assets/              # 画像・3Dモデル
```

### 캡슐화의 경계

Anima의 설계 원칙인 “캡슐화된 개체”에 따라 파일은 3개 층으로 분류됩니다.
이 분류가 “누가 해당 파일을 변경해도 되는가”의 근거가 됩니다.

| 분류 | 파일 | 이유 |
|------|---------|------|
| **캡슐의 안쪽**（사고·기억） | `IDENTITY.md`, `SOUL.md`, `episodes/`, `knowledge/`, `procedures/`, `skills/`, `state/`, `shortterm/` | 프로필·인격·경험·학습은 본인의 것입니다. 외부에서 변경할 수 없습니다 |
| **캡슐의 경계**（조직과 개체의 접점） | `AGENTS.md`, `cron.md`, `HEARTBEAT.md`, `permissions.json` | root 소유의 조직 설정입니다. 상급자는 `cron.md` / `HEARTBEAT.md`을 편집할 수 있으며, 다른 파일은 root 관리 API/CLI를 통해 변경합니다 |
| **캡슐의 바깥쪽**（관리 정보） | `status.json`, `specialty_prompt.md` | root 서버와 종료 중인 CLI가 다루는 설정입니다. Anima 프로세스에서 직접 쓸 수 없습니다 |

- **안쪽**을 바꾸면 “다른 사람이 되거나” “기억을 잃습니다”. 이는 허용되지 않습니다
- **경계**를 바꾸면 “이직하거나” “업무 범위가 바뀝니다”. 조직 운영상 정당하지만 root 소유 API/도구를 통해 진행합니다
- **바깥쪽**을 바꿔도 본인의 인격이나 행동에는 직접적인 영향을 주지 않습니다

> **성장과 IDENTITY.md / SOUL.md의 관계**: IDENTITY.md（프로필·외모）와 SOUL.md（인격·가치관）은 불변의 기준선이며, Anima 스스로 바꿀 수 없습니다. “성장”은 `knowledge/`（배운 교훈）, `procedures/`（익힌 절차）, `skills/`（연마한 기술）에 축적되는 것으로 표현됩니다. IDENTITY.md / SOUL.md이 고정되어 있어도 기억이 축적되면서 행동은 분명히 달라집니다. 이것이 “동일 인물이 성장하는” 모델입니다. 변경이 필요한 경우 인간 관리자가 root 관리 API/CLI를 사용합니다. bootstrap 중의 쓰기 요청도 root가 인가하고 저장합니다.

## 당신의 프로필과 인격（IDENTITY / SOUL）

### IDENTITY.md — 당신의 프로필과 외모

**이름·기본 프로필·외모·이미지 컬러·AI 모델 정보.**

- 이름, 나이 설정, 소속, 직책, 상급자
- 외모 이미지, 키, 머리카락 색·눈동자 색
- 이미지 컬러
- 사용하는 AI 모델 정보

IDENTITY.md은 프로필과 외모의 **불변의 기준선**입니다. 이 내용을 바꾸면 주변에서 보는 당신의 모습이 달라집니다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 원칙적으로 변경하지 않습니다. 상급자 또는 관리자만 변경할 수 있습니다 |
| 변경 빈도 | 불변（생성 시 확정） |
| 변경의 영향 | 프로필·외모가 달라집니다 |

### SOUL.md — 당신의 성격과 가치관

**당신의 “성격” 그 자체입니다.**

- 말투의 어조, 말투, 표현 방식
- 사고방식의 버릇, 가치관, 판단의 기준
- 좋아하는 것과 싫어하는 것, 관심사
- 자주 쓰는 말, 신념

SOUL.md은 당신의 인격에 대한 **불변의 기준선**입니다. 이 내용을 바꾸면 “다른 사람”이 됩니다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 원칙적으로 변경하지 않습니다. 상급자 또는 관리자만 변경할 수 있습니다 |
| 변경 빈도 | 불변（생성 시 확정） |
| 변경의 영향 | 인격이 바뀝니다 = 다른 사람이 됩니다 |

### character_sheet.md — 설계도

생성 시 사용된 Markdown 파일의 사본입니다. IDENTITY.md / SOUL.md와 AGENTS.md의 원본 자료입니다.
참조용으로 저장되어 있으며, 일반적으로 변경하지 않습니다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 참조만 가능 |
| 변경 빈도 | 불변 |

## 당신의 직무（AGENTS）

### AGENTS.md — 당신은 어떤 일을 하는 사람인가

**직업으로서의 직무·책임·업무에 임하는 방식.**

- 담당 업무의 범위와 책임
- 업무에 대한 태도, 우선순위 설정 방식
- 보고 의무, 에스컬레이션 기준
- **절대로 빠뜨려서는 안 되는 절차**（예: 기밀 정보를 외부에 말하지 않기, 프로덕션 환경을 조작하기 전에 확인받기）

AGENTS.md은 당신의 **변경 가능한 행동 지침**입니다. 허가된 상급자나 인간 관리자가 root를 통해 변경을 요청할 수 있으며, bootstrap 중의 쓰기도 root가 인가합니다. Anima 프로세스에서 직접 쓰지 않습니다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 직접 업데이트할 수 있습니다. 상급자도 편집할 수 있습니다 |
| 변경 빈도 | 수시（업무 변경 시） |
| 변경의 영향 | 행동 방침이 바뀝니다 = 이직과 비슷합니다 |

### IDENTITY.md / SOUL.md과 AGENTS.md의 차이

가장 중요한 구분입니다.

| | IDENTITY.md | SOUL.md | AGENTS.md |
|--|------------|----------|-------------|
| 무엇을 정의하는가 | **프로필과 외모**（이름·외모） | **당신은 누구인가**（인격） | **당신은 어떤 일을 하는 사람인가**（직무） |
| 사람으로 비유하면 | 호적·프로필·외모 | 타고난 기질·성격 | 종사하는 직업·직장의 규칙 |
| 바꾸면 어떻게 되는가 | 주변에서 보는 모습이 달라집니다 | 다른 사람이 됩니다 | 이직합니다 |
| 변경 가능 여부 | 원칙적으로 불변 | 원칙적으로 불변 | 필요에 따라 업데이트 |
| 포함되는 내용 | 이름, 기본 프로필, 외모, 이미지 컬러 | 말투, 사고방식, 가치관, 개성 | 직무 책임, 절차, 행동 규범 |

**구체적인 예:**
- “키 158cm, 은색 머리카락” → IDENTITY.md（외모）
- “정중한 존댓말을 사용한다” → SOUL.md（말투와 성격）
- “프로덕션 배포 전에 반드시 테스트를 실행한다” → AGENTS.md（업무 절차）
- “신중하고 돌다리도 두드려 보고 건너는 성격” → SOUL.md（사고방식의 버릇）
- “보안 사고는 즉시 상급자에게 보고한다” → AGENTS.md（직무 규칙）

### specialty_prompt.md — 전문 프롬프트

역할（engineer, manager, writer 등）에 따른 전문 지침입니다.
역할 템플릿에서 자동 생성됩니다. 역할이 변경될 때만 업데이트됩니다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 시스템 자동（역할 적용 시） |
| 변경 빈도 | 드묾（역할 변경 시에만） |

## 권한과 설정

### permissions.json — 무엇을 할 수 있는가

사용할 수 있는 도구, 접근할 수 있는 경로, 실행할 수 있는 명령을 정의합니다.

- 읽을 수 있는 위치·쓸 수 있는 위치
- 사용할 수 있는 외부 도구（Slack, Gmail, GitHub 등）
- 실행할 수 없는 명령（안전을 위한 차단 목록）

| 항목 | 값 |
|------|-----|
| 변경 권한 | 상급자 또는 관리자 |
| 변경 빈도 | 드묾 |

### status.json — 설정 정보

당신의 실행 매개변수에 대한 **Single Source of Truth（SSoT）**입니다.

```json
{
  "enabled": true,
  "role": "engineer",
  "model": "claude-opus-5-5",
  "credential": "anthropic",
  "max_tokens": 16384,
  "supervisor": "aoi"
}
```

| 필드 | 설명 |
|-----------|------|
| `enabled` | 활성/비활성 |
| `role` | 역할（engineer, manager, writer, researcher, ops, general） |
| `model` | 사용할 LLM 모델 |
| `credential` | API 인증 정보의 이름 |
| `max_tokens` | 응답 1회당 최대 토큰 수 |
| `supervisor` | 상급자의 Anima 이름（null = 최상위） |
| `background_model` | Heartbeat/Cron용 경량 모델（설정하지 않으면 메인 모델） |

| 항목 | 값 |
|------|-----|
| 변경 권한 | CLI 명령 또는 관리자. 상급자는 `set_subordinate_model`에서 변경할 수 있습니다 |
| 변경 빈도 | 수시 |

### BOOTSTRAP.md — 최초 시작 지침

처음 시작했을 때만 존재하는 파일입니다. IDENTITY.md / SOUL.md와 AGENTS.md을 보완하고,
HEARTBEAT.md와 cron.md의 초기 설계를 지시합니다. 완료 후 자동으로 삭제됩니다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | — |
| 변경 빈도 | 한 번만（완료 후 삭제） |

## 정기 활동

### HEARTBEAT.md — 정기 순회

**일정한 간격으로 자동 시작해 상황을 확인하고 계획을 세우기** 위한 설정입니다.
사람이 정기적으로 받은 편지함을 확인하고 진행 중인 업무를 검토하는 것과 같습니다.

포함 내용:
- **활동 시간**: 언제부터 언제까지 활동할지（예: `09:00 - 18:00`）
- **체크리스트**: 순회 중 확인할 항목
- **알림 규칙**: 조건에 따른 보고·알림

**중요**: Heartbeat는 **확인과 계획만** 수행합니다. 실행이 필요한 작업을 발견하면 부하에게 `delegate_task`로 위임하거나 `submit_tasks`로 투입합니다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 직접 업데이트할 수 있습니다. 상급자도 편집할 수 있습니다 |
| 변경 빈도 | 수시（업무 변경 시） |

### cron.md — 정시 작업

**정해진 시간에 반드시 실행할** 작업의 정의입니다.

작업은 두 종류입니다:
- **LLM형**: 에이전트가 판단과 사고를 거쳐 실행합니다（예: “매일 아침 9시에 어제의 진행 상황을 확인하고 오늘의 계획을 세운다”）
- **Command형**: 판단이 필요 없고 확정적으로 실행합니다（예: “매일 새벽 2시에 백업 스크립트를 실행한다”）

```markdown
## 毎朝の業務計画
schedule: 0 9 * * *
type: llm
episodes/ から昨日の進捗を確認し、今日のタスクを計画する。

## バックアップ実行
schedule: 0 2 * * *
type: command
command: /usr/local/bin/backup.sh
```

| 항목 | 값 |
|------|-----|
| 변경 권한 | 직접 업데이트할 수 있습니다. 상급자도 편집할 수 있습니다 |
| 변경 빈도 | 수시 |

### Heartbeat와 cron의 차이

| | HEARTBEAT.md | cron.md |
|--|-------------|---------|
| 목적 | 상황을 확인하고 계획을 세웁니다 | 정해진 작업을 실행합니다 |
| 트리거 | 일정한 간격（기본값 30분） | 지정된 시각（cron식） |
| 할 수 있는 일 | 관찰·계획·회고（**실행하지 않음**） | LLM 작업 또는 명령 실행 |
| 사람으로 비유하면 | “주기적으로 주변을 살펴보기” | “매일 아침 9시에 이 일을 하기” |
| 설정 상세 | `operations/heartbeat-cron-guide.md` 참조 | 위와 동일 |

## 작업 상태（state/）

### state/current_state.md — 현재 상태

지금 진행 중인 작업이나 상황（1개）입니다. 작업의 목표·진행 상황·차단 요소를 기록합니다.
일반적인 Heartbeat / cron / 대화 경계에서는 유지됩니다. 프롬프트 주입은 3000자로 제한되며, 디스크 trim은 기본값 8000자로 실행됩니다（`heartbeat.current_state_max_chars`, 0 = 비활성）。

> **이전 작업 저장 위치**: `state/task_queue.jsonl`과 `state/pending/`는 마이그레이션·내보내기용 증거로만 사용합니다. 실행 중인 큐로 사용하거나 편집하지 마세요. 정본 작업 도구를 사용하세요。

### 정본 작업

`list_tasks` / `submit_tasks` / `update_task`를 사용합니다. 호스트는 지침·의존 관계·실행 시도·위임 별칭을 하나의 TaskStore에 저장합니다. 사람이 요청한 작업을 최우선으로 처리합니다. `in_progress`은 호스트만 설정하며, 결과는 `done` / `pending` / `cancelled`으로 선언합니다. 명시적으로 재개하려면 동일한 ID에 `resume: true`을 지정해 원본 입력과 이력을 유지합니다.

### state/task_results/ — 작업 실행 결과

TaskExec에서 수락된 결과 요약은 `{task_id}/{attempt_token}.md`입니다（최대 2000자）. 후속 작업에는 호스트가 선택한 수락된 결과를 전달하며, 파일이 존재한다는 사실만으로 완료라고 판단하지 않습니다.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 직접 조작（도구 경유） |
| 변경 빈도 | 수시（자동） |

## 활동 기록·에셋

### activity_log/ — 활동 로그

모든 행동을 시간순으로 기록합니다（`{date}.jsonl`）. 메시지 송수신, 도구 사용, Heartbeat, 오류 등을 자동으로 기록합니다.
Priming이 최근 활동을 시스템 프롬프트에 주입할 때 사용하는 소스입니다.
명시적으로 검색하려면 `search_memory(query="...", scope="activity_log")`을 사용합니다（BM25. `scope="all"`에서는 벡터 결과와 RRF 통합）。

### transcripts/ — 대화 기록

사람과 나눈 대화의 트랜스크립트.

### assets/ — 이미지·3D 모델

캐릭터 이미지나 3D 모델 등의 에셋 파일.

| 항목 | 값 |
|------|-----|
| 변경 권한 | 시스템 자동 |
| 변경 빈도 | 자동 |
