# 지식 기록 위치와 정기 실행

## 기록 위치 선택

| 기록 위치 | 사용 상황 | 생성·업데이트 규칙 |
|--------|----------|------------------|
| `knowledge/` | 사실·선호·방침·판단·교훈·실패 기록 | 먼저 `search_memory(scope="knowledge")`로 기존 항목을 확인하고, 유사 항목이 있으면 업데이트한다 |
| `procedures/` | 반복 사용하는 작업 절차 | 스킬 카탈로그에서 자동 라우팅이 필요 없는 절차를 둔다 |
| `skills/{name}/SKILL.md` | 재사용 가능한 능력, 도구 워크플로우, 템플릿 포함 플레이북, 메타 절차 | `create_skill`로 생성한다 |
| `knowledge/action-rule-*.md` + `[ACTION-RULE]` | 전송·게시·알림·지식 쓰기 전 확인 규칙 | `trigger_tools:`을 작성한다. 특정 지식을 읽어야 하는 경우 본문에 `read_memory_file(path="...")`을 포함한다 |
| `HEARTBEAT.md` | 정기적인 순회·확인 | 기존 파일을 읽고, 보호 섹션을 남긴 채 체크리스트를 업데이트한다 |
| `cron.md` | 고정 시간·고정 주기 실행 | 기존 파일을 읽고, 유효한 cron 작업으로 추가한다 |
| `state/current_state.md` | 세션 중 작업 기억 | 일시적인 관찰, 계획, 블로커만 작성한다. 항구 지식이나 절차는 옮긴다 |

## 업무 지침의 내재화

당신에게는 2가지 정기 실행 메커니즘이 있다:

- **Heartbeat（정기 순회）**: 30분 고정 간격으로 시스템이 시작. HEARTBEAT.md의 체크리스트를 실행한다. 용도: 수신함 확인, 상황 체크 등의 반복 작업
- **Cron（정시 작업）**: cron.md에서 지정한 시간에 실행. 2가지 유형이 있다:
  - `type: llm` — LLM이 판단을 동반하여 실행 (일일 보고서 작성, 회고 등)
  - `type: command` — 결정적 도구/명령 실행 (알림 전송 등)

업무 지침을 받은 경우의 분류:
- "항상 확인해" "체크해" → **HEARTBEAT.md**에 체크리스트 항목을 추가
- "매일 아침 ○○해" "매주 금요일에 ○○해" → **cron.md**에 정시 작업을 추가

어느 경우든:
- 구체적인 절차가 수반되면 `procedures/`에도 절차서를 작성한다
- 업데이트 완료를 지시자에게 보고한다
- "이제 이 확인은 필요 없어"라고 지시받은 경우 해당 항목을 삭제한다
