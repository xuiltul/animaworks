# 지식 기록 위치와 정기 실행

## 기록 위치 선택

| 기록 위치 | 사용하는 경우 | 작성·업데이트 규칙 |
|--------|----------|------------------|
| `knowledge/` | 사실·선호·방침·판단·교훈·실패 기록 | 먼저 `search_memory(scope="knowledge")`에서 기존 내용을 확인하고, 유사한 내용이 있으면 업데이트한다 |
| `procedures/` | 반복해서 사용하는 작업 절차 | 스킬 카탈로그의 자동 라우팅이 필요 없는 절차를 둔다 |
| `skills/{name}/SKILL.md` | 재사용 가능한 역량, 도구 워크플로, 템플릿이 포함된 플레이북, 메타 절차 | `create_skill`에서 작성한다 |
| `knowledge/action-rule-*.md` + `[ACTION-RULE]` | 전송·게시·알림·기억 기록 전 확인 규칙 | `trigger_tools:`을 작성한다. 특정 기억을 읽어야 하는 경우 본문에 `read_memory_file(path="...")`을 포함한다 |
| `HEARTBEAT.md` | 정기 순회·확인 | 기존 파일을 읽고, 보호 섹션을 남겨둔 채 체크리스트를 업데이트한다 |
| `cron.md` | 정해진 시각·주기에 따른 실행 | 기존 파일을 읽고, 유효한 cron 작업으로 추가한다 |
| `state/current_state.md` | 세션 중 작업 기억 | 일시적인 관찰, 계획, 차단 요인만 작성한다. 영구 지식이나 절차는 옮긴다 |

## 업무 지침의 내재화

정기 실행 메커니즘은 두 가지가 있다:

- **Heartbeat(정기 순회)**: 시스템이 30분 간격으로 시작된다. HEARTBEAT.md의 체크리스트를 실행한다. 용도: 받은 편지함 확인, 상태 점검 등의 반복 작업
- **Cron(예약 작업)**: cron.md에서 지정한 시각에 실행된다. 두 종류가 있다:
  - `type: llm` — LLM이 판단을 수반해 실행(일일 보고서 작성, 회고 등)
  - `type: command` — 결정론적인 도구/명령 실행(알림 전송 등)

업무 지침을 받았을 때의 분류:
- 「항상 확인해」「점검해」→ **HEARTBEAT.md**에 체크리스트 항목을 추가
- 「매일 아침 ○○해」「매주 금요일에 ○○해」→ **cron.md**에 예약 작업을 추가

두 경우 모두:
- 구체적인 절차가 수반되는 경우 `procedures/`에도 절차서를 작성한다
- 업데이트 완료 사실을 지시자에게 보고한다
- 「이제 이 확인은 필요 없어」라는 지시를 받은 경우 해당 항목을 삭제한다
