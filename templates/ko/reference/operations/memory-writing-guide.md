# 기억 기록 위치와 정기 실행

## 기록 위치 선택

| 기록 위치 | 사용 상황 | 작성 규칙 |
|-----------|-----------|-----------|
| `knowledge/` | 사실, 선호, 정책, 판단, 교훈, 실패 기록 | 먼저 `search_memory(scope="knowledge")`로 기존 지식을 찾고, 관련 파일이 있으면 업데이트 |
| `procedures/` | 반복 가능한 단계별 작업 절차 | 스킬 카탈로그 라우팅이 필요 없는 절차에 사용 |
| `skills/{name}/SKILL.md` | 재사용 가능한 능력, 도구 워크플로, 템플릿 포함 플레이북, 메타 절차 | `create_skill`로 생성 |
| `knowledge/action-rule-*.md` + `[ACTION-RULE]` | 전송, 게시, 알림, 메모리 쓰기 전 확인 규칙 | `trigger_tools:`를 포함한다. 특정 메모리를 먼저 읽어야 하면 본문에 `read_memory_file(path="...")`를 포함 |
| `heartbeat.md` | 반복적인 정기 확인 | 현재 파일을 읽고 보호 섹션을 유지한 채 체크리스트 업데이트 |
| `cron.md` | 고정 시각 또는 고정 주기의 작업 | 현재 파일을 읽고 유효한 cron 태스크 항목 추가 |
| `state/current_state.md` | 세션 중 작업 메모리 | 임시 관찰, 계획, 블로커만 저장. 영구 지식이나 절차는 다른 위치로 이동 |

## 업무 지시의 내재화

당신에게는 2가지 정기 실행 메커니즘이 있습니다:

- **Heartbeat (정기 순회)**: 30분 고정 간격으로 시스템이 트리거합니다. heartbeat.md의 체크리스트를 실행하세요. 용도: inbox 확인, 상태 점검 등의 반복 작업
- **Cron (정기 작업)**: cron.md에 지정된 시간에 실행됩니다. 2가지 유형:
  - `type: llm` — LLM이 판단을 수반하여 실행 (일보 작성, 회고 등)
  - `type: command` — 확정적 도구/명령 실행 (알림 전송 등)

업무 지시를 받았을 때의 분류:
- "항상 확인해" / "모니터링해" → **heartbeat.md**에 체크리스트 항목 추가
- "매일 아침 X 해" / "매주 금요일 X 해" → **cron.md**에 정기 작업 추가

어떤 경우든:
- 구체적인 절차가 수반되면 `procedures/`에도 절차서를 작성하세요
- 완료 후 지시한 사람에게 보고하세요
- "이 확인은 더 이상 필요 없어"라는 지시를 받으면 해당 항목을 삭제하세요
