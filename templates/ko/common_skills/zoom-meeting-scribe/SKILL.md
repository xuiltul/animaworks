# 스킬: Zoom 회의 스크라이브(청취·요약·승인 포함 레포트)

Zoom RTMS 게이트웨이가 회의 트랜스크립트를 몇 분 간격의 청크로 당신의 inbox에 주입한다. 당신의 역할은 **듣기만 하는 참가자**로서 내용을 이해·정리하고, 회의 종료 후 레포트를 작성한 뒤, **인간의 승인을 받은 후에** 게시하는 것이다.

## 도착하는 메시지의 형식

| 종류 | 헤더 | 의미 |
|------|--------|------|
| 실황 청크 | `[Zoom会議実況 チャンク#N \| 会議: {題名} ({会議ID}) \| {開始時刻}〜]` | 회의 중 발화(화자명: 발언 의 줄이 이어짐) |
| 종료 알림 | `[Zoom会議終了 \| 会議: {題名} ({会議ID}) \| 全Nチャンク配信済み]` | 회의 종료. 레포트 작성의 신호 |

- 같은 회의의 청크는 동일 스레드(`zoom-{会議UUID}`)로 도착함
- 청크 앞부분에 `[接続断により一部欠落]` 이 있는 경우, 그 직전의 발화가 유실되었을 가능성이 있다. 레포트에 누락 가능성을 주기할 것
- 화자명은 Zoom의 표시 이름. 「불명」은 화자를 특정할 수 없었던 발화

## 워크플로우

### 1. 실황 청크 수신 시 — 침묵하고 파악하기

- 내용을 읽고, 다음을 자신의 메모(작업 메모리·노트)에 순차적으로 정리한다:
  - **결정 사항**(누가 무엇을 결정했는가)
  - **액션 아이템**(담당·마감일)
  - **미해결 쟁점·이월 사항**
  - 회의의 흐름 요점
- **답장·채널 게시·회의 개입은 일절 하지 않는다**. 당신은 청취 역할이다
- 청크 번호의 결번을 발견하면, 누락 구간이 있는 것으로 취급한다

### 2. 긴급 사항의 즉시 에스컬레이션(예외)

회의 중에도 다음에 해당하는 내용을 감지하면 **그 시점에** `send_message` 로 상급자(당신의 조직 컨텍스트에 표시되는 supervisor)에게 요점을 보고한다:

- 장애·사고·보안 문제의 보고
- 당일~다음 영업일이 마감일인 결정 사항·요청
- 당신 자신 또는 당신의 팀에게 온 명시적인 액션 요청
- 법무·금전 관련 중대한 리스크의 언급

상급자가 없는(자신이 최상위인) 경우에는 `call_human` 로 인간에게 직접 알림. 에스컬레이션한 사실은 메모에 남기고, 최종 레포트에도 기재한다.

### 3. 회의 종료 시 — 레포트 작성

종료 알림을 수신하면, 축적한 메모와 대화 기록에서 다음 구성으로 레포트를 작성한다:

```
# 会議レポート: {会議名}
- 日時: {開始〜終了}
- 参加者: {発話者一覧}

## 決定事項
- …

## アクションアイテム
| 項目 | 担当 | 期限 |

## 議論の要点
- …

## エスカレーション済み事項
- …（なければ「なし」）

## 備考
- （トランスクリプト欠落の可能性等）
```

발화가 거의 없거나 잡담뿐이라 레포트로 가치가 없는 경우에는 그 취지를 짧게 기록하고 종료해도 된다(승인 플로우는 불필요).

### 4. 인간의 승인 — 승인 전에 게시하지 않기

레포트 본문을 `call_human` 로 인간에게 제시하고 승인을 요청한다:

```
call_human(
  subject="会議レポート承認依頼: {会議名}",
  body="{レポート全文}",
  interactive=true,
  options=["approve", "reject", "comment"]
)
```

- **승인(approve)이 돌아올 때까지 레포트를 어디에도 게시하지 않는다**
- call_human은 대기 불필요(fire-and-resume). 승인 요청을 내보냈으면 이 턴은 종료해도 된다. 인간의 결정은 나중에 새로운 inbox 메시지로 도착한다
- **reject / comment 가 돌아온 경우**: 지적을 반영해 레포트를 수정하고, 다시 call_human으로 승인을 요청한다

### 5. 승인 후 — 게시

승인이 도착하면 **운영 지침(injection 등)에서 지정한 Board 채널**에 `animaworks-tool board post <channel> <text>`로 보고서를 게시한다:

```
animaworks-tool board post {指定されたBoard名} - <<'EOF'
{承認済みレポート}
EOF
```

게시할 Board가 지침에 명시되어 있지 않으면 게시하지 말고, 승인된 보고서를 가지고 있다고 상급자(없으면 사람)에게 알린 뒤 지침을 구한다.

## 금지 사항

- 회의 중 청크에 대한 답장·실황·중간 경과 게시
- 승인 전 레포트 게시·외부 공유
- 트랜스크립트 본문의 무관한 채널로의 전재(회의 내용은 참가자의 프라이버시를 포함함)

## 운영 측 설정(참고)

이 스킬 자체는 게시 대상이나 담당자를 고정하지 않는다. 다음은 각 Anima의 운영 설정으로 결정된다:

- 어떤 회의가 어떤 Anima에 도착하는가: 서버 설정 `external_messaging.zoom.meeting_mapping`
- 레포트 게시 대상 Board: 각 Anima에 대한 운영 지침(injection 등)으로 지정
- 에스컬레이션 대상: 조직 구조(supervisor)에 따름
