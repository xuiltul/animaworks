# 用例：基础设施与服务监控

对服务器、Web服务、云资源等进行365天24小时监控，实现异常检测、告警和初步响应的自动化用例。

---

## 可以解决这些问题

- 发现服务器宕机太晚
- 夜间、节假日无法进行故障处理
- 漏看SSL证书的截止日期
- 没有察觉磁盘容量或资源耗尽
- 监控工具的告警太多，漏掉重要的告警

---

## 模式1：Web服务的存活监控

### 要做的事
定期检查Web服务是否正常响应，异常时发出告警。

### 运行流程
1. 按固定间隔（例如：每5〜30分钟）访问目标URL
2. 确认HTTP响应代码、响应时间
3. 检测到异常时：
   - 第1次：重新确认（可能是临时错误）
   - 连续2次：通知人类
   - 检测到恢复后发送恢复通知
4. 记录响应时间的变化趋势，检测劣化倾向

### 应用示例
- 生产Web网站返回503 → 立即通知管理者的手机
- API响应比平时慢3倍 → 性能劣化警告
- 维护结束后的恢复确认 → 自动确认并报告正常恢复

### 开始所需的条件
- 监控目标的URL列表
- 告警通知目的地（聊天、邮件等）
- 判定标准（多少秒以上视为延迟等）

---

## 模式2：服务器资源监控

### 要做的事
监控CPU、内存、磁盘容量、进程状态等服务器资源。

### 运行流程
1. 定期获取服务器状态（通过SSH或API）
2. 将各指标与阈值比较：
   - 磁盘使用率 > 80% → 警告
   - 磁盘使用率 > 95% → 紧急通知
   - 内存使用率急剧上升 → 疑似内存泄漏
   - CPU高负载持续 → 检查进程失控
3. 如有异常，通知告警和推荐应对措施

### 应用示例
- 磁盘容量只剩5% → 提示可删除的旧日志候选
- 特定进程持续占用CPU 100% → 报告进程名和启动时间
- 内存使用量逐日增加 → 警告可能存在泄漏

### 自动应对示例
- 日志轮转（压缩、删除旧日志文件）
- 识别并报告失控进程（自动终止需经人类批准）
- 清理临时文件

## 模式3：SSL/TLS证书的截止日期监控

### 要做的事
定期检查SSL证书的有效期，在到期前促更新。

### 运行流程
1. 每天1次确认目标域名的证书有效期
2. 根据剩余天数变更告警级别：
   - 剩余30天 → 信息通知（推荐准备更新）
   - 剩余14天 → 警告通知（请尽快更新）
   - 剩余7天 → 紧急通知（需要立即处理）
3. 发送附有更新步骤的提醒

### 应用示例
- 批量管理多个域名的证书截止日期
- 确认Let's Encrypt等自动更新是否正常运行
- 验证更新后的证书是否正确应用

---

## 模式4：云服务监控

### 要做的事
监控云上资源（容器、数据库、存储等）的状态和费用。

### 运行流程
1. 使用云API定期获取资源状态
2. 监控以下内容：
   - 服务的运行状态（正常/异常）
   - 错误日志的发生情况
   - 成本变化趋势（检测预算超支）
3. 检测到异常或预算超支时通知

### 应用示例
- 容器服务的任务数减少 → 疑似服务故障
- 数据库的连接数接近上限 → 建议扩容
- 本月云费用超过预算的80% → 成本警告

---

## 模式5：日志分析与异常检测

### 要做的事
定期分析应用日志，检测错误模式和异常趋势。

### 运行流程
1. 获取指定期间的日志
2. 统计错误、警告的发生件数
3. 与平时比较判定异常：
   - 错误率为平时的3倍 → 调查告警
   - 出现新类型的错误 → 疑似新故障
   - 特定端点错误集中 → 该功能故障
4. 将分析结果作为摘要报告

### 应用示例
- “过去30分钟错误0件，正常” → 常规报告
- “检测到3件新的错误模式” → 附上详情报告
- “特定API的错误率急剧上升” → 开始原因调查

---

## 模式6：集成仪表盘式运营

### 要做的事
整合多个监控结果，定期生成摘要报告。

### 运行流程
1. 汇总各监控负责方的报告
2. 整理成一眼就能看清整体状态的摘要
3. 定期（例如：每天早上9点）向人类报告

### 报告示例
```
== 本日のインフラ状況 ==
[正常] Webサービス: 応答正常（平均120ms）
[正常] サーバーリソース: CPU 15%, メモリ 45%, ディスク 62%
[注意] SSL証明書: example.com の期限まで残り20日
[正常] クラウドサービス: 全タスク稼働中
[正常] エラーログ: 過去24時間のエラー 0件
```

## 配置建议

### 最小配置（Anima 1个）
- 由1个Anima巡回监控所有项目
- 巡回间隔约30分钟
- 小规模环境（服务器1〜2台）足够

### 推荐配置（Anima 3〜4个）
- **监控统筹**：把握整体状态、判断异常、升级处理
- **服务器监控**：监控OS、进程、资源
- **网络/SSL监控**：监控SSL证书、DNS、连通性
- **云监控**：监控云服务特有的内容

### 减少误报的技巧
- 不要因1次异常就立即告警（连续2次确认）
- 阈值以实际环境的平常值为基准设置
- 建立由统筹方独立验证监控Anima报告的体制
- 将误报模式作为知识积累，提升判定精度
