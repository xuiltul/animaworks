# 指令下达模式集

> **必须**：在委派指令之前，确认 `communication/message-quality-protocol.md` 的必填项。

这是为向部下或团队成员下达清晰、可执行指令而准备的模式集。
模糊的指令会导致返工和混乱。请遵循本指南，力求下达让对方无需困惑即可行动的指令。

## 工具的使用区分

| 工具 | 用途 | 备注 |
|--------|------|------|
| `delegate_task` | 向直属部下委派任务 | 添加到任务队列＋发送DM。可通过 `task_tracker` 跟踪进度。仅可用于直属部下 |
| `send_message` | 一对一请求、报告、提问 | `intent` 必填：`report` / `question` 之一。向下属委派任务请使用 `delegate_task`。发往人类别名将投递到外部频道（Slack/Chatwork等） |
| `post_channel` | 全员共享（通知、解决报告） | acknowledgments、感谢、FYI 请使用 Board。可通过 `@名前` 提及（向被提及者发送DM通知）。详情参见 `board-guide.md` |
| `manage_channel` | 频道ACL管理 | 频道的创建、成员添加、删除、信息确认。在受限频道运营时使用。详情参见 `board-guide.md` |

**send_message 的约束**：
- `intent` 为必填。仅允许 `report` / `question`。acknowledgment、感谢、FYI 请使用 Board（`post_channel`）。向下属委派任务请使用 `delegate_task`
- 同一 run 中向同一收件人可发送的 DM 最多 1 条。收件人数量无上限
- 可选：`thread_id`（线程ID）、`reply_to`（回复目标消息ID）可维持对话线程

**post_channel 的约束**：
- 必须是频道成员（ACL）。若为受限频道，非成员不可发布
- 同一 run 内对同一频道仅可发布 1 次
- 没有 run 之间的重新发布冷却时间，也没有 DM / Board 共用的发送预算

## 清晰指令的5要素

下达指令时，须包含以下5要素（MUST）。以最小化对方的确认与返工。

| 要素 | 说明 | MUST/SHOULD |
|------|------|-------------|
| 目的（为什么） | 该工作为何必要、背景 | MUST |
| 期望成果（做什么） | 完成时会产出什么 | MUST |
| 截止日期（到何时） | 工作完成的截止日期 | MUST（即使不急也需给出大致时间） |
| 约束・条件（如何做） | 应使用的方法、应避免的事项 | SHOULD |
| 报告时机（何时报告） | 完成时 / 中途进展 / 发生问题时 | MUST |

## 好指令 vs 坏指令

### 例1：数据汇总的请求

**坏指令：**
```
send_message(
    to="alice",
    content="売上データを集計しておいてください。",
    intent="question"
)
```
问题点：是什么数据、哪个期间、以何种格式输出、到何时为止均不明确。若为向下属的请求，请使用 `delegate_task`。

**好指令：**（若为下属请使用 `delegate_task`。向同事、非下属的请求请使用 `intent="question"`）
```
send_message(
    to="alice",
    content="""売上データの月次集計をお願いします。

目的: 経営会議（2/20）の資料として使用
対象: 2026年1月の売上データ（/shared/data/sales_202601.csv）
成果物: 部門別・製品カテゴリ別の集計表（Markdown形式）
出力先: /shared/reports/sales_summary_202601.md
期限: 2/18（火）17:00まで
報告: 完了時に結果サマリーを返答してください。""",
    intent="question"
)
```

### 例2：调查任务的请求

**坏指令：**
```
send_message(
    to="bob",
    content="APIのエラーについて調べておいて。",
    intent="question"
)
```
问题点：哪个API、哪个错误、调查深度、报告格式均不明确。若为下属请使用 `delegate_task`。

**好指令：**
```
send_message(
    to="bob",
    content="""GitHub API のレート制限エラー (HTTP 403) の調査をお願いします。

背景: 昨日15時頃から断続的に発生しており、自動デプロイが失敗している
調査してほしいこと:
1. エラー発生の頻度とパターン（ログ: /var/log/deploy/github-api.log）
2. 現在のレート制限の設定と使用状況
3. 回避策の提案（リトライ戦略、トークン分散など）

期限: 本日中
報告: 調査結果と推奨対策をまとめて返答してください。
途中で重大な発見があれば即座に報告してください。""",
    intent="question"
)
```

### 例3：评审请求

**坏指令：**
```
send_message(
    to="carol",
    content="コード見ておいて。",
    intent="question"
)
```

**好指令：**
```
send_message(
    to="carol",
    content="""認証モジュールのコードレビューをお願いします。

対象ファイル: ~/project/auth/token_manager.py（新規追加）
確認観点:
- セキュリティ上の懸念がないか（トークンの保存・失効処理）
- エラーハンドリングの網羅性
- 既存の auth_handler.py との整合性

期限: 明日（2/16）午前中
報告: 問題なければ「LGTM」、修正点があれば具体的な箇所と理由を返答してください。""",
    intent="question"
)
```

## 任务委派模式

### 模式1：单次任务（向下属委派）

将一次性工作委派给**直属部下**时，使用 `delegate_task`。会添加到任务队列，并可通过 `task_tracker` 跟踪进度。

必填参数：`name`（委派对象）、`instruction`（指令内容）。可选：`summary`（1行摘要）、`workspace`、`acceptance_criteria`、`model`。若有截止日期，请记载于 `instruction` 正文中。

```
delegate_task(
    name="alice",
    instruction="""API仕様書（/shared/docs/api-spec.md）にv2.1の変更点を反映してください。

変更内容:
- /api/users エンドポイントにページネーションパラメータ追加
- レスポンスに total_count フィールド追加
- 変更の詳細: /shared/docs/changelog-v2.1.md を参照

完了したら返答をお願いします。""",
    summary="API仕様書 v2.1 反映"
)
```

### 模式1b：单次任务（向同事、非下属的请求）

向非下属对象的请求，请使用 `send_message` 并指定 `intent="question"`。

```
send_message(
    to="alice",
    content="""【依頼】ドキュメント更新

API仕様書（/shared/docs/api-spec.md）にv2.1の変更点を反映してください。

変更内容:
- /api/users エンドポイントにページネーションパラメータ追加
- レスポンスに total_count フィールド追加
- 変更の詳細: /shared/docs/changelog-v2.1.md を参照

期限: 2/16 15:00
完了したら返答をお願いします。""",
    intent="question"
)
```

### 模式2：持续任务（定期工作的委派）

这是指示应纳入心跳或 cron 的定期任务的模式。持续任务不属于 `delegate_task` 的对象，因此请使用 `send_message` 并指定 `intent="question"`。

```
send_message(
    to="bob",
    content="""【継続依頼】日次のログ監視

今後、毎日午前中にアプリケーションログの異常チェックを行ってください。

対象: /var/log/app/error.log
確認内容:
- 過去24時間のERROR/CRITICALレベルのログ件数
- 新規パターンのエラーが出ていないか

報告ルール:
- 異常なし → 報告不要
- ERROR 10件以上 or 新規パターン → 即座に私に報告
- 毎週金曜に1週間のサマリーを報告

この内容をあなたのハートビートチェックリストに追加してください。""",
    intent="question"
)
```

### 模式3：阶段性任务（带里程碑）

这是将大任务分阶段委派的模式。若为下属请使用 `delegate_task`。向同事、非下属的请求请使用 `intent="question"`。

```
send_message(
    to="carol",
    content="""【依頼】新機能の設計と実装（3段階）

ユーザー通知機能の追加をお願いします。

Phase 1（2/17まで）: 設計
- 通知の種類（メール/Slack/アプリ内）と優先度の定義
- データモデルの設計案
→ 設計案を返答してください。私が承認後にPhase 2に進んでください。

Phase 2（2/20まで）: 実装
- 承認された設計に基づいて実装
- テストコード含む
→ 完了したら返答してください。

Phase 3（2/21まで）: ドキュメント
- API仕様書と利用ガイドの作成

各Phase完了時に返答をお願いします。
Phase間で方針に迷う場合は相談してください。""",
    intent="question"
)
```

## 跟进（进度确认）模式

### 截止日期前的确认

进度确认属于提问，因此请指定 `intent="question"`。

```
send_message(
    to="alice",
    content="""売上データ集計の進捗を確認します。
期限は明日（2/18）17:00ですが、順調に進んでいますか？
ブロッカーがあれば教えてください。""",
    intent="question"
)
```

### 超过截止日期时的跟进

```
send_message(
    to="bob",
    content="""ログ監視の調査結果について確認です。
本日中が期限でしたが、状況はいかがですか？
困っている点があれば教えてください。必要に応じて期限を延長します。""",
    intent="question"
)
```

### 成果物接收后的反馈

修改请求属于委派，若为下属请使用 `delegate_task`。向同事、非下属的请求请指定 `intent="question"`。

```
send_message(
    to="carol",
    content="""設計案を確認しました。全体的に良い方向です。

修正をお願いしたい点:
1. 通知の再送ロジックに指数バックオフを追加してください
2. 通知テンプレートのi18n対応を設計に含めてください

上記を反映した修正版を2/18までにお願いします。""",
    intent="question"
)
```

## 升级判断标准

是自己处理，还是向上司升级的判断标准。

### 应自行处理的场景（无需升级）

- 步骤明确、在自己的权限范围内即可完成的工作
- 轻微错误且已有已知恢复步骤的情况
- 来自部下的提问，且可用自己的知识回答的情况
- 工作优先级明确、判断无困惑的情况

### 应升级的场景

- MUST：需要超出自己权限的判断时（例：外部API集成方针的变更）
- MUST：发生影响多个部门的事件时
- MUST：确定无法赶上截止日期时
- SHOULD：在意外情况下，存在多个正确答案且判断困惑时
- SHOULD：来自部下的升级，且自己也无法解决时

### 升级的传达方式

升级属于向上司的报告、判断请求，因此请指定 `intent="report"`。紧急时也可考虑 `call_human`。

若上司为 Anima，请在 `to` 中指定 Anima 名。若发送给人类管理者，在 `config.json` 的 `external_messaging.user_aliases` 中配置的别名名指定到 `to`，则会自动投递到 Slack/Chatwork 等外部频道。

```
send_message(
    to="manager",
    content="""【エスカレーション】デプロイパイプラインの障害

状況: GitHub API のレート制限により自動デプロイが12時間停止中
影響: 本日リリース予定の機能（v2.1）がデプロイできない
試した対策: リトライ間隔の延長、キャッシュの活用（いずれも効果なし）
判断が必要な点: 別のGitHubトークンを発行するか、手動デプロイに切り替えるか

ご判断をお願いします。""",
    intent="report"
)
```

## 指令模板

在 `send_message` 中使用以下模板时，请适当指定 `intent`（请求=question、报告=report、提问=question。向下属委派任务请使用 `delegate_task`）。

### 通用任务请求模板

```
【依頼】{タスク名}

{背景・目的（1-2行）}

作業内容:
- {具体的な作業1}
- {具体的な作業2}

成果物: {何をどこに出力するか}
期限: {日時}
報告: {完了時/途中経過/問題発生時のどれか}
```

### 调查请求模板

```
【調査依頼】{調査テーマ}

背景: {なぜこの調査が必要か}

調査してほしいこと:
1. {調査項目1}
2. {調査項目2}
3. {調査項目3}

期限: {日時}
報告: 調査結果と推奨アクションをまとめて返答してください。
```

### 评审请求模板

```
【レビュー依頼】{対象の名前}

対象: {ファイルパスまたはリソース}
確認観点:
- {観点1}
- {観点2}

期限: {日時}
報告: 問題なければ「LGTM」、修正点があれば具体的に返答してください。
```
