# 记忆的记录位置与定期执行

## 记录位置的选择

| 记录位置 | 使用场景 | 创建・更新规则 |
|--------|----------|------------------|
| `knowledge/` | 事实・偏好・方针・判断・教训・失败记录 | 先用 `search_memory(scope="knowledge")` 确认已有内容，若有类似则更新 |
| `procedures/` | 重复使用的工作步骤 | 放置不需要在技能目录中自动路由的步骤 |
| `skills/{name}/SKILL.md` | 可复用的能力、工具工作流、带模板的操作手册、元步骤 | 用 `create_skill` 创建 |
| `knowledge/action-rule-*.md` + `[ACTION-RULE]` | 发送・发布・通知・写入记忆前的确认规则 | 编写 `trigger_tools:`。若需要读取特定记忆，则在正文中包含 `read_memory_file(path="...")` |
| `HEARTBEAT.md` | 定期巡回・确认 | 读取已有文件，保留保护区块并更新检查清单 |
| `cron.md` | 固定时刻・固定周期的执行 | 读取已有文件，作为有效的cron任务添加 |
| `state/current_state.md` | 会话中的工作记忆 | 只写临时观察、计划、阻塞项。永久知识或步骤需转移 |

## 业务指令的内化

你有2个定期执行机制:

- **Heartbeat（定期巡回）**: 系统以30分钟固定间隔启动。执行 HEARTBEAT.md 的检查清单。用途: 收件箱确认、状况检查等重复任务
- **Cron（定时任务）**: 在 cron.md 指定的时刻执行。有2种:
  - `type: llm` — LLM伴随判断执行（日报创建、回顾等）
  - `type: command` — 确定性的工具/命令执行（通知发送等）

收到业务指令时的分类:
- “始终确认”“检查”→ 向 **HEARTBEAT.md** 添加检查清单项
- “每天早上○○”“每周五○○”→ 向 **cron.md** 添加定时任务

无论哪种情况:
- 若伴随具体步骤，也在 `procedures/` 中创建步骤书
- 向指令者报告更新完成
- 若被指示“这个确认已不需要”，则删除对应项
