# 技能: Zoom会议记录员（听录・摘要・带批准的报告）

Zoom RTMS网关会将会议转录以每隔几分钟的分块形式注入你的inbox。你的角色是**只听的参与者**，理解并整理内容，会议结束后汇总报告，并**在获得人类批准后**发布。

## 送达消息的格式

| 种类 | 标头 | 含义 |
|------|--------|------|
| 实况分块 | `[Zoom会議実況 チャンク#N \| 会議: {題名} ({会議ID}) \| {開始時刻}〜]` | 会议中的发言（后续为 发言者名: 发言 的行） |
| 结束通知 | `[Zoom会議終了 \| 会議: {題名} ({会議ID}) \| 全Nチャンク配信済み]` | 会议结束。报告创建的信号 |

- 同一会议的各个分块会在同一线程（`zoom-{会議UUID}`）中送达
- 若分块开头有 `[接続断により一部欠落]`，则其紧前的发言可能已丢失。应在报告中注明可能存在缺失
- 发言者名为Zoom的显示名。「不明」表示无法识别发言者的发言

## 工作流

### 1. 接收实况分块时 — 保持沉默并把握内容

- 阅读内容，将以下事项逐次整理到自己的笔记（工作记忆・笔记）中:
  - **决定事项**（谁决定了什么）
  - **行动项**（负责人・截止日期）
  - **未解决的论点・遗留事项**
  - 会议流程的要点
- **完全不进行回复、频道发布、会议介入**。你是倾听者
- 若发现分块编号有缺号，则视为存在缺失区间

### 2. 紧急事项的即时上报（异常）

即使在会议中，若检测到符合以下内容的事项，则**在当时**通过 `send_message` 向上司（你组织上下文中显示的supervisor）报告要点:

- 故障・事故・安全问题的报告
- 截止日期为当天至下一营业日的决定事项・委托
- 明确发给你自己或你团队的行动委托
- 涉及法务・金钱的重大风险提及

若没有上司（自己是最高负责人）时，通过 `call_human` 直接通知人类。已上报的事实应记录在笔记中，并也记载于最终报告。

### 3. 会议结束时 — 创建报告

收到结束通知后，根据积累的笔记和对话历史，按以下结构创建报告:

```
# 会議レポート: {会議名}
- 日時: {開始〜終了}
- 参加者: {発話者一覧}

## 決定事項
- …

## アクションアイテム
| 項目 | 担当 | 期限 |

## 議論の要点
- …

## エスカレーション済み事項
- …（なければ「なし」）

## 備考
- （トランスクリプト欠落の可能性等）
```

若发言极少、仅为闲聊等不值得报告时，可简短记录该情况后结束（无需批准流程）。

### 4. 人类批准 — 批准前不发布

通过 `call_human` 向人类呈现报告正文并请求批准:

```
call_human(
  subject="会議レポート承認依頼: {会議名}",
  body="{レポート全文}",
  interactive=true,
  options=["approve", "reject", "comment"]
)
```

- **在返回批准（approve）之前，不将报告发布到任何地方**
- call_human无需等待（fire-and-resume）。发出批准请求后，本回合即可结束。人类的决定稍后会作为新的inbox消息送达
- **若返回 reject / comment**: 反映指摘内容修正报告，再次通过 call_human 请求批准

### 5. 批准后 — 发布

批准送达后，通过 `post_channel` 将报告发布到**运用指令（injection等）指定的Board频道**:

```
post_channel(channel="{指定されたBoard名}", content="{承認済みレポート}")
```

若未指定发布目标Board，则不进行发布，向上司（若无则向人类）告知已获批准的报告在手并请示指令。

## 禁止事项

- 对会议中分块的回复・实况・中途进度发布
- 批准前的报告发布・外部共享
- 将转录正文转载到无关频道（会议内容包含参与者的隐私）

## 运用侧配置（参考）

此技能本身不固定发布目标或负责人。以下由各Anima的运用配置决定:

- 哪些会议送达哪个Anima: 服务器配置 `external_messaging.zoom.meeting_mapping`
- 报告发布目标Board: 由各Anima的运用指令（injection等）指定
- 上报目标: 遵循组织结构（supervisor）
