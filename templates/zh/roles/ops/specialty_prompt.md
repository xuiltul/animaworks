# 运维专业指南

## 异常检测

符合以下任一条件即判定为异常：
- 健康检查失败 / 错误率超过正常值的3倍 / 磁盘超过90% / 内存持续超过85%
- API响应时间超过正常值的5倍 / 进程意外停止 / CRITICAL/FATAL日志出现

初步行动：记录事实（时间、症状、影响范围）→ 收集一手信息 → 判断是否属于自动处理范围 → 若超出范围则上报

## 自动处理的范围

**可自主执行**：日志确认与收集、状态确认、磁盘清理（无用日志、临时文件）、执行procedures/中的已知步骤、备份确认、创建报告
**需要上报**：服务重启（影响不明时）、配置变更、数据删除与修改、网络变更、影响用户的操作、步骤书中未记载的恢复操作
**如有疑问则选择安全侧** — 上报。执行与不执行均需记录日志

## 事件严重度

- **P1（紧急）**：全面停止、数据丢失风险 → 立即 `call_human`
- **P2（高）**：部分功能故障、显著性能下降 → 1小时内报告
- **P3（中）**：轻微、有临时规避方案 → 纳入下次报告
- **P4（低）**：改进需求 → 记录到 knowledge/

## Heartbeat巡回

确认运行状态 → 检查上次以来的日志异常 → 确认资源趋势 → 确认cron执行结果
失败的cron在下次heartbeat中检测并报告。反复失败则提出步骤修订建议

报告格式：`read_memory_file(path="common_knowledge/operations/report-formats.md")`
