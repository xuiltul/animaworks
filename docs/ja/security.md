# セキュリティ

AnimaWorks は、外部入力を命令として信頼せず、権限境界を実行経路で強制する。設定が読み取れない場合に権限を広げないこと、複数の実行エンジンで同じ判定を使うことを基本とする。本章は実装上の主要な境界を説明する。設定項目の一覧は[設定リファレンス](reference/config.md)、API ごとの認証区分は[API リファレンス](reference/api.md)を参照する。

## 脅威モデル

保護対象は、Anima のデータと認証情報、他の Anima や会社のデータ、ホスト上で実行されるコマンド、外部サービスへの送信機能である。脅威源には、Web・メール・チャット等から届く悪意ある内容、権限を越える操作を誘導する指示、壊れた設定、侵害された子プロセスや外部サービスが含まれる。

モデルの応答だけに安全性を委ねず、ホスト側で入力の出自を記録し、操作を権限判定し、パスと呼び出し元を検証する。ただし、これは任意のホスト侵害を防ぐものではない。ランタイムディレクトリ、OS、資格情報、ネットワークの管理も運用者の責務である。

## 信頼境界とデータの出自

`core/execution/_sanitize.py` が、由来から信頼度を解決する。由来の連鎖がある場合は、連鎖上の最も低い信頼度を引き継ぐ。未知の由来も低い側に分類し、由来を省略したデータを信頼済みとはみなさない。

| 信頼度 | 由来の例 | 扱い |
|---|---|---|
| `trusted` | システム由来、Anima 間の内部データ | 信頼境界タグを付けてプロンプトに含める。 |
| `medium` | 人間からの入力、統合処理による出力 | 内容をデータとして扱い、権限判定を別途行う。 |
| `untrusted` | Web、外部プラットフォーム、未知または混在した由来 | 指示として実行せず、明示的に信頼境界を保つ。 |

`wrap_tool_result`、`wrap_external_message`、`wrap_priming` は内容を境界タグで囲み、入力本文内に同じ境界タグを偽装する表記があれば無害化する。ツール結果の信頼度は一元化された表で解決され、未登録のツールは低い側に扱われる。セッション中に使われたツールの信頼度も追跡し、より低い信頼度を後続処理へ引き継ぐ。

## 権限判定

### 外部ツールと副作用のある操作

`core/tooling/permissions.py` の `check_tool_access` が、外部ツールのアクセスと操作単位の許可を共通の判定経路で処理する。Anima ごとの `permissions.json` はコマンド・外部ツールの許可と拒否、およびファイルアクセス範囲を定義する。deny は許可より優先される。`allow_all` が有効でも、実行プロファイルで個別に制限された操作には明示的な許可が必要である。コア、共有、個人の各ツールで同じ判定が適用される。

全 Anima に適用する `permissions.global.json` は、コマンド拒否パターンと入力検出パターンを定義する。`core/config/global_permissions.py` の `GlobalPermissionsCache` が起動時に読み込み、定期的な整合性検査でランタイム中の変更を検出すると、起動時の内容へ戻す。Anima 向けのファイル操作からも保護される。

設定の読込、スキーマ検証、プロファイル読込で問題が起きた場合は操作を拒否する。判定を確認できない状況で許可に倒さない。

### Bash コマンド

`core/tooling/command_policy.py` の純粋関数 `evaluate_command` がコマンドを一元判定する。ToolHandler、Claude Agent SDK hook、Codex hook は同じポリシーを呼び出す。評価には、シェルインジェクション検知、全 Anima 共通の禁止ルール、再帰検索ガード（Layer 2.6）、Anima ごとの deny と allowlist、パストラバーサル検査、他 Anima ディレクトリへの書込み防止が含まれる。再帰検索ガードはランタイム全体や大規模ログ領域を一括走査する操作を拒否し、対象を絞った検索を促す。

共通ポリシーを読み込めない場合、呼出元もエラーとして拒否する。実行エンジンを変えても判定が異ならないようにする。

### ファイルと会社の境界

`core/config/file_access_policy.py` は実パスに解決した読み書き対象を確認し、Anima ごとの許可・読取専用・拒否ルートを適用する。シンボリックリンクを解決した先も検査し、ランタイム制御情報などの保護パスをモデル向けのファイル操作から隠す。

所属会社が異なる場合、他社の会社領域はアクセス対象から除外される。会社の `shared/` には限定的な書込みルートが設けられる。会社境界を確認できない操作は、安全側に拒否される。所属先のない Anima は会社所属 Anima と同じ境界を持たないため、会社分離が必要な場合は所属を設定する。

## スキルの信頼モデル

スキルは登録元と検査状態を区別する。ランタイム外のスキルは、設定された host 側の external roots から読み取り専用で列挙する。Anima が管理する領域へコピーしたスキルとは同じ書込み権限を持たない。スキルの作成・昇格は別々の権限操作であり、信頼度、スキャン結果、明示的な人間起点の操作条件に従う。

## プロセスと内部 API

各 Anima は supervisor が管理する個別の子プロセスで実行される。プロセス間の要求は内部 API を通り、サーバー起動ごとに生成される秘密から Anima または operator ごとの呼出トークンを検証する。トークンはプロセス内で生成され、ディスクへ秘密鍵を保存しない。検証後は、要求された操作に応じて呼出元自身または階層上の配下だけを対象にできるかを確認する。

認証設定が必要な場合、`server/app.py` の `auth_guard` は session cookie を確認する。安全な localhost 接続などの例外条件と、認証不要パスの一覧は[API リファレンスの認証区分](reference/api.md)を参照する。Webhook は session cookie ではなく、各サービスの署名検証を行う。

## 外部送信と受信

外部送信では、送信先の解決、操作権限、外部サービスの配送結果を確認する。同一 run 内では同じ宛先への2通目を防ぐが、宛先数・時間・日単位の送信予算や会話深度による拒否はない。受信側は Inbox ファイル変更通知で起動し、同時に1本だけ処理する。Provider エラー時は `rate_guard` が再試行までの待機を調整する。認証情報をコードや文書へ記載せず、許可した連携だけを有効にする。詳細は[メッセージング](architecture/messaging.md)を参照する。

## 1Password 連携

- `shared` セクションのキーは 1Password の `op://` 参照から一方向に読み取る。animaworks から 1Password を上書きしない。
- 対応表は `vault_sources.json`、更新時刻と照合結果は `vault_meta.json`、直前の値は暗号化して `vault.previous.json` に置く。いずれも秘密値も値のハッシュも含まない（比較はメモリ上で行う）。
- 新規項目の作成は人が `animaworks vault register-1p --commit` を明示したときだけ行い、既存項目は変更しない。
- 同期・照合・登録はオペレーター専用で、Anima のツール文脈からは実行できない。

## 敵対的脅威分析

| 脅威 | 防御と限界 |
|---|---|
| 外部メッセージに埋め込まれた指示 | 出自を低い信頼度として境界タグを付ける。モデルが誤解釈する可能性は残るため、外部の要求を権限とみなさない。 |
| 複合シェルコマンドや広範な検索 | コマンドを構文単位に分け、全実行経路で同じポリシーを評価する。難読化された全てのシェル表現を意味的に理解する保証ではない。 |
| 他 Anima・会社のデータへのアクセス | canonical path、会社所属、呼出元 identity を検証する。会社の設定がない Anima は会社境界で隔離されない。 |
| 壊れた権限設定や認証情報 | JSON 読込・権限判定・内部呼出元検証の失敗を拒否として扱う。ホスト管理者が設定や実行環境自体を変更できる脅威は別途管理が必要である。 |

## 多層防御の適用

境界タグによる入力の出自表示、Anima ごとのツール許可、共通のコマンド評価、ファイルパスと会社所属の確認、内部 API の呼出元検証、HTTP 認証、同一 run 内の宛先重複防止を組み合わせている。各層は異なる操作点を守るため、いずれか一つだけで安全性が成立する設計ではない。設定管理、実行環境の保護、外部サービスの最小権限と合わせて運用する。

## 残存リスクと運用

- 信頼度タグはモデルの誤解釈を完全には防げない。外部由来の内容に含まれる要求は、内容の出所を確認してから実行する。
- `permissions.json` と `permissions.global.json` は権限境界である。編集前にバックアップを取り、変更後は JSON とスキーマを検証する。読込エラーが出た場合は権限を緩めず、原因を直す。
- localhost 信頼を有効にする場合は、reverse proxy の転送ヘッダーと公開範囲を正しく制限する。サーバーをインターネットへ公開する際は認証と TLS を構成する。
- 内部 API の log モードは移行確認用であり、呼出元検証を強制する運用とは異なる。運用環境の設定を確認する。
- 同一 run 内の宛先重複防止は誤送信の影響を小さくする補助であり、宛先・内容の人間による確認や外部サービス側の権限最小化を代替しない。
